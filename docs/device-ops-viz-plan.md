# 设备页运维可视化 — 设计定稿与分期

> 定稿时间：2026-10-23 Asia/Shanghai  
> 仓库：`Wink-XZ-Li/tuya-ops-console`（本机 worker：`~/Developer/tuya-ops-console`）  
> 状态：**已定稿，待按刀开发**（本轮先做 P0）  
> 相关：一阶段故障看板；二阶段售后作业（字典第 1 刀已在 `cursor/fault-code-dictionary-30a7`；待办/关单/webhook **仍暂停**，本线不重启）

---

## 1. 目标与原则

在 **设备详情页** 分区展示运维可视化，让售后/产品扫单机即可：故障史、参数走势、用量、连通与状态。

原则：

1. **故障与连通性拆开**（默认列表不含离线；连通另块展示）
2. **口径先于图表**（空窗不插假 0；累计清零有说明）
3. **每刀只服务一个证明对象**
4. **只读优先**：P0 不做设备页关单；关单仍走告警页（售后关单/webhook 线暂停中）

---

## 2. 信息架构（设备详情自上而下）

1. 状态集（现有）
2. **P0 历史故障**
3. **P1 参数走势**
4. **P2 用量**（无 `usageMetrics` 配置则整块隐藏）
5. **P3** 连通时间条 / 状态时间条 / 变更锚点（可拆版）
6. 固件 / 云日志 / 事件（现有；可与 P3 锚点联动）

## 3. P0 — 历史故障清单

### 证明对象

打开任意设备详情，不用翻原始事件，就能 **一眼扫完** 这台机质量故障的开闭历史。

### 放置

状态集卡片下方、固件/日志上方；标题「历史故障」；右侧快捷：近 7 天 / 近 30 天 / 全部（**默认近 30 天**）。

### UI

时间线（非宽表）：

- **主行**：状态色点（未关闭=红/橙，已关闭=灰）· 故障码 · 字典短名/症状（一行截断）· 右侧相对时间（如「3 天前开」/「已关 · 持续 2h」）
- **辅行**（首屏完整展示约 5 条，其余「展开更多」）：建议动作 · `occurrenceCount` · 关闭原因（`auto_clear` / `manual` / … → 人话）
- **顶部小结**：`未关闭 N · 近 30 天新开 M · 最长一次持续 …`（N/M 可点筛选）

### 数据与过滤

- 只读 `Alert`：`deviceId = 当前设备` 且 `category = 'fault'`（含 closed）
- **默认不含** `connectivity`；页内开关「含离线」默认关
- 排序：未关闭置顶，其余按 `openedAt` / `conditionStartedAt` 倒序
- 分页：首屏 20 条，「加载更多」

### 接口

`GET /api/devices/:deviceId/fault-history?from=&to=&includeConnectivity=0&cursor=`

返回：告警字段 + join 字典的 `symptom` / `suggestedAction` + `summary`。不新建工单表。

### 明确不做

设备页关单、webhook、跨设备汇总、改写一阶段记账逻辑。

### 验收

1. 有未关闭故障时，该条置顶且红色点醒目  
2. 同码多次开闭能看到多条历史，不只当前活跃一条  
3. 字典有文案时症状/建议可见；无文案时至少显示码  
4. 默认列表看不到纯离线告警；打开「含离线」后可见且视觉区分

## 4. P1 — DP / 参数走势

### 证明对象

单机上用曲线回答「这段时间关键参数怎么走」。

### 放置

「历史故障」下方；标题「参数走势」。默认收起为「常用 DP」折叠条，点开后出图。

### 图表

- 时间：近 24h / 近 7 天 / 近 30 天（默认近 7 天）；可选手动起止（上限 90 天）
- 多选数值型 DP；同图多线；图例可隐藏
- 粒度：24h → 5min；7d → 1h；30d → 1d；每桶 **avg / min / max**（阴影带 min–max，折线 avg）
- 空窗断线，**不插 0**

### DP 选择

- 仅数值型；布尔/枚举留给 P3 状态条
- 默认：产品 `defaultTrendDps`；若无则取近 7 天上报次数 Top3 数值 DP
- 勾选按 `productId` 记 `localStorage`

### 接口

`GET /api/devices/:deviceId/dp-trends?dpIds=a,b&from=&to=&bucket=1h`  
→ `{ series: [{ dpId, name, unit, points: [{ t, avg, min, max }] }] }`  
不做实时 WebSocket；刷新/切区间再拉。

### 交互

- 悬停：时间 + avg（及 min/max）
- 「对比故障」开关（默认关）：叠 P0 开闭竖线/色块
- 无数据空态可读（可提示桥接/长期离线，不做成故障分析）

### 明确不做

用量换算、导出 CSV、跨设备对比、异常自动打标、改告警规则。

### 验收

1. 切区间后粒度与阴影带正确，空窗无假 0  
2. 默认 DP 合理；勾选按产品记住  
3. 「对比故障」与 P0 时间对齐  
4. 无时序不报错

## 5. P2 — 用量图

### 证明对象

把「用了多少」换成可读的日柱 + 区间累计。

### 放置

「参数走势」下方；标题「用量」；无 `usageMetrics` 则整块隐藏。

### 产品配置 `usageMetrics[]`（示例）

| metricId | 展示名 | 来源 | mode | 单位 |
|----------|--------|------|------|------|
| water | 用水量 | 累计水表 DP 差分 / 瞬时流量积分 | cumulative \| instant | L / m³ |
| gas | 用气量 | 累计气量差分 | cumulative | m³ |
| energy | 用电量 | 电表差分或功率积分 | cumulative \| instant | kWh |

配置字段：`sourceDpId`、`mode`、`unit`、`scale`。P2 优先累计差分，其次瞬时积分。

### 图表

- 近 7 / 30 天日柱（默认 7）+ KPI：`本区间合计` · `日均` · `峰值日`
- 多 metric：Tab/小卡切换
- 可选对比上周/上月浅柱；**不做**自动异常告警
- 无上报日缺口，不造 0

### 口径

- 日桶：设备时区默认 Asia/Shanghai `00:00–24:00`
- 累计差分：`day_end − day_start`；负差当重置，当日记重置后增量；页脚注明
- 瞬时积分：桶内 `avg × 时长`，缺测不断补

### 接口

`GET /api/devices/:deviceId/usage?metric=water&from=&to=`  
→ `{ unit, total, dailyAvg, peakDay, days: [{ date, value }], note }`

### 与 P1 边界

走势 = 工程量级 DP 曲线；用量 = 换算后的「用了多少」。可同源 DP，文案分块。

### 明确不做

账单、分时电价、多表汇总、对账 CSV、用量尖刺自动写故障。

### 验收

1. 仅配置了 usage 的产品显示本块  
2. 合计/日均/峰值与柱一致  
3. 累计清零不出现负日用量，页脚有说明  
4. 无数据日无假高峰

## 6. P3 — 其它可视化（可拆）

### P3a 在线/离线时间条

近 7 天色带：绿=在线、灰=离线、浅=未知。数据来自连通性事件；与故障分色分块。

### P3b 关键状态时间条

枚举/布尔 DP（如燃烧/待机/防冻）；产品 `statusBarDps[]`；未配置不显示。

### P3c 固件与关键变更锚点

在 P1 图或时间条打竖线：固件变更、（可选）远程指令成功点；无记录不打点。不做因果结论。

### 明确不做（P3 及以后暂缓）

跨设备大盘、自动根因、用量→故障规则、客户账单、地图热力、炫酷大屏。

## 7. 分期交付表

| 刀 | 范围 | 证明对象 | 依赖 |
|----|------|----------|------|
| **P0** | 故障时间线 + 小结 + 字典 join | 单机故障史可读 | Alert + 字典（一阶段 / 二阶段第 1 刀） |
| P1 | 数值 DP 走势 + 可选叠故障 | 工况曲线可读 | DP 时序或可聚合事件 |
| P2 | 用量日柱 + KPI + usage 配置 | 「用了多少」可读 | 累计/瞬时换算配置 |
| P3a | 在线时间条 | 连通与故障拆开看见 | 连通性事件 |
| P3b | 状态时间条 | 模式切换可见 | 枚举 DP 配置 |
| P3c | 固件/指令锚点 | 变更与曲线对齐 | 已有变更记录 |

**开发顺序**：P0 → P1 → P2 → P3a → P3b → P3c。每刀单独分支/PR，验收通过再开下一刀。
