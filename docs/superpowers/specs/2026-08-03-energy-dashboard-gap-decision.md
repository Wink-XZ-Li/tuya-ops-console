# 相对「能耗监管大屏」的能力缺口 · 产品决策

**日期：** 2026-08-03  
**对照站点：** https://service-000-250420007166.us-west1.run.app/（门店能耗监管演示，前端 MOCK）  
**本仓库：** 涂鸦 OEM 设备运维控制台（设备 / 用户 / 告警 / 指令 / 星象仪运营看板）

---

## 1. 产品方向（已确认）

**选择：继续做 OEM 运维台，只借鉴对方若干能力形态；不做门店能耗监管产品线。**

依据：

- 对方是「门店 → 区域 → 设备」的 **能源管理 / 节能策略** 产品；核心 KPI 是功率、kWh、节省费用、节能率。
- 我们是「用户/家庭 → 设备」的 **智能家居运维台**；核心 KPI 是激活、活跃、注册、控制次数，并已对接涂鸦 OpenAPI / MQ。
- 业务方已确认后台类型不同；后续产品赋能方向是用户画像、设备使用、故障分析、运营报表（见同目录后续分析蓝图），而非能耗大屏。

| 路径 | 结论 |
|------|------|
| 做成能耗监管产品线 | **否** — 需重建领域模型与数据源，与当前 Demo/授权能力错位 |
| 借鉴若干能力 | **是** — 见 §4 |

---

## 2. 门店 / 区域 / 能耗数据源（不对齐能耗方向 → 明确不做）

对方依赖且我们 **不会** 引入的模型：

| 对方能力 | 为何不做 |
|----------|----------|
| 门店 CRUD（连锁/楼宇/小微/工厂） | 无门店主数据；组织单元是 App 用户与家庭 |
| 区域 CRUD + 设备挂载树 | 无楼层/区域资产模型；设备仅有 lat/lon/`locationText` |
| 电表/网关功率与电能汇聚 | 未建能耗时序仓；部分 PID 虽有功率/用电 DP，仅最新 `statusJson` 快照 |
| 基准负荷 vs 实际负荷、节省费用算法 | 无营业时段/电价/基准策略约定，无计费域 |

**OEM 侧等价「聚合」**（若以后要借鉴「空间聚合视图」语义，用现有数据，不建门店树）：

- 按 **产品 PID** 聚合在线/故障/告警
- 按 **省/市地理** 聚合（星象仪地区分布 + 设备 `locationText` 可读化后）
- 按 **用户/家庭** 下钻设备（已有用户详情）

功率/电能若进入分析，也只作为 **单品 DP 使用分析**（设备使用分析的一环），不做成门店能耗监管。

---

## 3. 策略引擎与能耗大屏（不对齐 → 明确不做）

对方有、我们 **不会** 照搬：

| 对方模块 | 结论 |
|----------|------|
| 能耗监管大屏（总功率/今日 kWh/节能率/负荷曲线/门店 Top） | **不做** |
| 节能策略（时间/环境/设备规则、云端 vs 边缘、节省归因） | **不做** 独立策略产品 |
| 品类/品牌/协议映射主数据 UI | **不做** 商业网关接入叙事；保留现有 PID 白名单 + DP schema + 别名 |
| 能耗报表中心（门店排名/能耗趋势导出） | **不做** 能耗主题；报表能力改做 **运营周月报** |

**OEM 侧可借鉴的「策略化」弱形式**（非节能策略引擎）：

- 批量运维动作：按筛选结果批量指令 / 确认（建立在现有 `CommandPanel` + 权限上）
- 可配置告警阈值：离线分钟数、故障码关注列表（扩展现有 offline job / Alert，而非能耗超阈）
- 报表导出：周报/月报 CSV（用户/设备/故障指标），而非门店 kWh 报表

## 4. 从对方可借鉴、且符合 OEM 方向的能力

| 对方表象 | 借鉴成 OEM 能力 | 本仓库现状 | 后续归属 |
|----------|-----------------|------------|----------|
| 按门店/区域切换视角 | 按产品 / 地区 / 时间窗统一筛选下钻 | 看板有日期与 productId | 分析页统一筛选 |
| 设备状态汇总 + 实时告警条 | 机群健康 + 故障趋势 | 告警列表有；无聚合趋势 | 故障分析 |
| 导出报表 | 运营周/月报 + CSV | 无 | 报表中心 |
| 策略执行状态 | 批量指令结果汇总（成功/失败） | 仅单设备指令日志 | 批量运维（后置） |
| 大屏自动刷新 | 关键看板可选自动刷新 | 设备详情状态 5s 轮询 | 可选增强 |

**明确不抄：** 暗色能耗指挥大屏、门店排名、基准负荷、边缘 Edge Box 执行、品牌/Modbus 接入向导。

---

## 5. 能力缺口对照（归档）

对方有而我们没有、且 **因方向决策而关闭** 的项：

1. 能耗 KPI 与负荷曲线大屏  
2. 门店 → 区域 → 设备树  
3. 节能策略引擎与节省归因  
4. 品类/品牌/协议资产台账  
5. 设备通信配置 / 协议接入向导  
6. 能耗统计与门店报表  
7. 能耗/电压类阈值告警  

对方弱、我们更强、应继续建设的底座：

- 真实涂鸦 OpenAPI + MQ + DB  
- App 用户 / 家庭  
- JWT RBAC 与指令审计

## 6. 待办结论

| 原待办 | 结果 |
|--------|------|
| 确认对齐「借鉴」还是「能耗产品线」 | **已确认：借鉴若干能力，不做能耗产品线** |
| 定门店/区域模型与功率电能数据源 | **关闭** — 不引入该领域模型；OEM 用 PID/地理/家庭聚合 |

下一步产品实现应以 **产品赋能运维分析**（用户画像、设备使用、故障分析、运营报表）为准，而非本对照站点的能耗域。
